# ZATCA release boundary and verification

Production submission remains blocked in code. Environment flags, a company
preference, an SDK result, or a locally generated QR do not establish authority
acceptance. No taxpayer credentials belong in this document, logs or Git.

## Current application behavior

| Mode | Application behavior | Verification boundary |
|---|---|---|
| Local generation (default) | Generates and stores invoices with the app's five-field Phase 1 TLV QR. Nothing is submitted. | The QR is generated by this app; it is not issued by ZATCA and does not prove authority acceptance. |
| Sandbox or simulation | Supports explicit non-production gateway configuration, onboarding and retained test evidence. | Test results must remain labelled with their environment. They do not establish production approval. |
| Production | Onboarding, signing/issuance routing and network submission remain unavailable. | A separate reviewed release and independent taxpayer/authority validation are required. |

The official SDK is an offline validation tool. Its successful checks do not
prove that the configured taxpayer, EGS device, certificate or first real
submission has been accepted by the authority. Confirm the taxpayer's actual
requirements and integration notice through the official Fatoora portal.

## Non-production configuration

Use the existing ignored environment-file setup or the hosting platform's
protected environment settings. Configure the app and its database for the
same isolated staging project before testing. Do not mix staging and production
keys or copy credentials into commands, prompts, reports or screenshots.

- Explicit offline mode: `ZATCA_MODE=mock` with no gateway URL.
- Sandbox: `ZATCA_MODE=sandbox` and exactly
  `https://gw-fatoora.zatca.gov.sa/e-invoicing/developer-portal`.
- Simulation: `ZATCA_MODE=simulation` and exactly
  `https://gw-fatoora.zatca.gov.sa/e-invoicing/simulation`.

Missing, mismatched or malformed gateway configuration fails closed. A
production mode or a production gateway cannot become simulated success.
The app validates the gateway in the shared server-side configuration boundary.

## Company preference recovery

The existing `zatca_tenant_environment` table can contain a historical ON
preference. Migrations preserve that value; they do not enable, disable or
backfill company preferences. Reading a missing preference successfully means
OFF; a database error or malformed response means unavailable, not OFF.

Accounting → E-invoicing (ZATCA) shows the stored preference separately from the
effective gateway. A stored ON preference does not silently route to simulation.
Production ON is visibly unavailable. An active, appropriately authenticated
accounting approver can save OFF to recover an existing preference.

Recovery uses `save_my_zatca_environment` with the request ID and shared company
configuration version that the user reviewed. The database derives actor and
tenant, locks the tenant row, checks current authorization, and commits state,
version, required audit and durable receipt together. Exact retries return their
historical receipt without undoing later changes. Direct service-role writes
are blocked even after the upstream table grant migration.

Stale or uncertain save outcomes lock further writes until an explicit reload.
Do not assume a failed response means the transaction rolled back; reconcile
its result before another intent. Existing invoices, evidence and preferences
from other companies remain unchanged by recovery.

## Test-gateway verification

1. Apply the reviewed source migrations to an isolated database with their
   correct history. Preserve alternate already-applied histories; do not mark a
   repository migration applied blindly or replay archived migrations.
2. Complete the company's tax profile and National Address in Settings → Company.
3. Use the matching non-production portal and a synthetic, authorized test
   identity to onboard an EGS unit. Enter an OTP only in the app; never record it
   in evidence. The private key and CSID secret must remain server-side.
4. Verify invoice, credit-note and debit-note cases, monetary/source binding,
   numbering, signature/QR data and retained evidence. Verify failures and retry
   behavior as well as successful test responses.
5. Check per-document status and the gateway's own evidence. A transport HTTP
   status, stored preference or green UI badge alone is insufficient.
6. Verify the printed QR is bound to the appropriate retained test artifact and
   clearly disclosed as non-production. Local Phase 1 QR output stays explicitly
   described as app-generated.

Automatic submission remains opt-in. The adapter rechecks the current operator
and permissions, retains issuance/transmission evidence, and refuses to confirm
success when required evidence cannot be persisted. Documents before the
configured EGS registration cutoff are not retrospectively submitted by that
stream. Test backlog totals and failed/rejected outcomes with isolated fixtures.

## Production release gate

This release does not open the core gateway. Setting
`ZATCA_MODE=production` and `ZATCA_PRODUCTION_ENABLED=true` still fails closed;
the company switch cannot bypass that boundary.

A future production change needs independently reviewed authority validation,
correct taxpayer/device onboarding and certificate handling, source-bound
issuance/transmission safeguards, and observed acceptance of the intended
production flows. The reviewed SDK evidence and production-runtime PDF
comparison must correspond to the actual released signer and renderer. Preserve
an audit trail of the real authority result without exposing secrets.

The database's support for the word `production` is a compatibility capability,
not approval to submit. Migration `20261030090000_zatca_production_toggle.sql`
does not remove the guarded switch's direct-write trigger or its required audit.

## Coordinated deployment and operations

Use the repository's tested feature-branch, PR, CI, migration and deployment
workflow. Match the deployed commit to the intended environment and verify it.
Do not treat local tests as a fresh production backup or hosted cutover rehearsal.
Do not roll back application code across incompatible SQL without the reviewed
maintenance/recovery plan. Production secrets and live business records require
the user's explicit authorization before changing them.

Monitor failed test submissions, backlog and certificate expiry. Review operator
access when staff or roles change. A deployment configuration error, revoked
operator, unreadable company preference or missing evidence must stop the
submission path rather than select another environment or report success.
